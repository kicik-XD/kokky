# kokky

Музыкальный плеер в тёмном минималистичном стиле — HTML, CSS и ванильный JS.
Интерфейс повторяет референс, но под брендом **kokky**.

## Что внутри

- **Живая лента SoundCloud** без вшитых подборок: при запуске собираются популярные
  треки по нескольким жанровым запросам, а поиск идёт по всему каталогу SoundCloud.
- Раздел **«Плейлисты»**: квадратная кнопка **«создать плейлист»**, свои плейлисты
  сохраняются в `localStorage`.
- После создания плейлист открывается: внутри можно добавлять треки через поиск,
  убирать их и запускать весь список.
- На «Моём потоке» кнопка **«Добавить в плейлист»** рядом с перемоткой — выбираете,
  в какой из своих плейлистов положить текущий трек. То же действие есть в меню `⋯`.
- Источник — **SoundCloud**: полные треки, без аккаунта, подписки и API-ключей.
  Отрывки длиной 30 секунд (`policy: SNIP`) отфильтровываются.
- Воспроизведение идёт через **официальный SoundCloud Widget** — легальный встроенный
  плеер. Он живёт в блоке `#scPlayer` за обложкой и управляется через Widget API.
- Поиск работает в два слоя: мгновенно по загруженной ленте и через живой поиск
  по всему каталогу (с задержкой 260 мс и защитой от гонок).
- Полноценное управление: перемотка, пауза, следующий/предыдущий трек, автопереход,
  громкость, лайки и плейлисты с сохранением в `localStorage`.
- Горячие клавиши: `Space` — пауза, `←/→` — ±5 сек, `↑/↓` — громкость, `/` — поиск.
- Адаптивная мобильная версия с нижней навигацией.
- Логотип и кнопка play — обычные треугольники.

## Запуск

Самый простой способ — **дважды кликнуть `start.bat`** в папке `kokky`. Скрипт поднимет
локальный сервер и откроет `http://localhost:8000` в браузере.

Можно и вручную:

```powershell
cd C:\Users\Admin\kokky
python -m http.server 8000
```

и открыть `http://localhost:8000`.

Открывать `index.html` двойным кликом (`file://`) нельзя: браузер не даёт виджету
SoundCloud работать со страницы `file://`. Приложение показывает подсказку и кнопку
**«Как запустить»**.

## Как устроен звук

- Воспроизведение: **SoundCloud Widget API** (`https://w.soundcloud.com/player/api.js`).
  Плеер создаётся в `#scPlayer` внутри обложки и управляется через
  `load`, `play`, `pause`, `seekTo`, `setVolume`, `getDuration`, события
  `PLAY` / `PAUSE` / `FINISH` / `PLAY_PROGRESS` / `ERROR`.
- Поиск: `https://api-v2.soundcloud.com/search/tracks` с публичным `client_id`.
  SoundCloud не отдаёт CORS, поэтому запрос идёт через прокси:
  по умолчанию публичный `r.jina.ai` (без ключа). Свой прокси задаётся в
  `library.soundcloud.proxy` — см. `worker/README.md`.
- Лента собирается из нескольких жанровых запросов (`feedQueries` в `library.js`),
  сортируется по прослушиваниям, перемешивается и кэшируется в `localStorage`
  (`kokky:feed:sc`), чтобы плеер сразу открывался с треками даже при медленной сети.
- Обложки — `artwork_url` SoundCloud в размере 500×500.

## Ограничения SoundCloud

- Некоторые треки правообладатель закрыл для вашей страны: виджет сообщает об ошибке,
  плеер автоматически переключает на следующий трек.
- В бесплатном тарифе SoundCloud может вставлять аудиорекламу — это часть официального
  плеера, убрать её нельзя.
- Публичный `client_id` может однажды перестать работать. Тогда его нужно заменить в
  `library.js` (`soundcloud.clientId`) на актуальный из веб-клиента SoundCloud.
- `r.jina.ai` имеет лимит запросов. Для стабильной публичной версии разверните свой
  воркер-прокси (папка `worker/`) и укажите его в `library.soundcloud.proxy`.
- На мобильных браузерах автозапуск со звуком заблокирован: первый трек запускается
  нажатием **play**, дальше автопереход работает.

## Файлы

- `index.html` — разметка, SVG-иконки и контейнер SoundCloud-плеера
- `styles.css` — дизайн, адаптив, анимации
- `app.js` — плеер, лента, поиск, плейлисты, лайки, меню, клавиатура
- `library.js` — источник, `client_id`, прокси и жанровые запросы
- `start.bat` — запуск локального сервера и открытие плеера в браузере
- `assets/` — локальный аватар профиля
